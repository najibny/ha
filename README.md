# نظام التحديث اللحظي للأصناف — الحلواني

تطبيق ويب عربي (RTL) يعمل لحظيًا على الهواتف والأجهزة اللوحية واللابتوب وشاشات الكول سنتر،
مبني بـ HTML + CSS + JavaScript صِرف ومتصل فعليًا بـ **Supabase** (قاعدة بيانات + تحديث لحظي).

## 2) إنشاء مشروع Supabase (خطوة بخطوة)

1. افتح [supabase.com](https://supabase.com) وأنشئ حسابًا مجانيًا إن لم يكن لديك.
2. اضغط **New Project**، اختر اسمًا (مثلًا `halawany`) وكلمة مرور لقاعدة البيانات، واختر منطقة قريبة.
3. انتظر حتى يكتمل إنشاء المشروع (دقيقة أو دقيقتين).
4. من القائمة الجانبية اذهب إلى **SQL Editor** → **New query**.
5. افتح ملف `supabase/schema.sql` من هذا المشروع، انسخ **كل محتواه**، والصقه في محرر SQL بالكامل.
6. اضغط **Run**. سيُنشئ هذا كل الجداول والدوال والسياسات، ويضيف بيانات أولية (أقسام + رموز PIN تجريبية + 3 أصناف تجريبية).
7. تأكد أن التنفيذ اكتمل بدون أخطاء (يظهر "Success" أسفل المحرر).

## 3) أين أضع رابط Supabase والمفتاح العام

1. من لوحة تحكم Supabase اذهب إلى **Project Settings** (⚙️) → **API**.
2. انسخ:
   - **Project URL** (يشبه `https://xxxxxxxxxxx.supabase.co`)
   - **anon public key** (مفتاح طويل يبدأ عادة بـ `eyJ...`)
3. في مجلد المشروع، انسخ الملف `js/config.example.js` وأعد تسميته إلى `js/config.js`.
4. افتح `js/config.js` وضع القيمتين:

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJ...المفتاح-العام-فقط",
  APP_NAME: "الحلواني",
  EARLY_OUT_OF_STOCK_HOUR: 15
};
```

> ⚠️ **لا تضع أبدًا** مفتاح `service_role` هنا. فقط `anon public key`. مفتاح anon آمن للاستخدام في الواجهة لأن كل التعديلات الحساسة تمر عبر دوال RPC محمية داخل قاعدة البيانات.

## 5) النشر على Cloudflare Pages أو Netlify

### Netlify
1. اسحب مجلد المشروع بالكامل (بعد إضافة `js/config.js`) إلى صفحة **Netlify Drop** (app.netlify.com/drop)، أو اربط مستودع Git.
2. لا حاجة لأي إعداد بناء (Build command فارغ)، مجلد النشر هو المجلد الرئيسي نفسه.

### Cloudflare Pages
1. من لوحة Cloudflare اذهب إلى **Pages** → **Create a project** → **Direct Upload** أو اربط مستودع Git.
2. ارفع مجلد المشروع كما هو (لا حاجة لأمر بناء).

> تأكد أن ملف `js/config.js` مرفوع مع المشروع في النشر (هو الملف الوحيد الذي يحتوي على بيانات مشروعك).

## 6) تغيير رموز PIN التجريبية

بعد التشغيل الأول، رموز PIN التجريبية هي:
- كل الأقسام الإنتاجية + الكول سنتر: **1234**
- الإدارة: **9999**
- المطور مجد: **0000**

**غيّرها فورًا** بإحدى الطريقتين:

**أ) من داخل الموقع (الطريقة الموصى بها):**
سجّل الدخول بجهة "المطور مجد" بالرمز `0000`، ثم من تبويب **"رموز PIN"** في لوحة المطور، اكتب رمزًا جديدًا مكوّنًا من 4 أرقام لكل جهة واضغط حفظ.

**ب) عبر SQL مباشرة:**
```sql
select public.set_department_pin(
  (select id from public.departments where code = 'baklawa'),
  '5678'
);
```

## 7) الأدوار المتاحة

| الجهة | الصلاحيات |
|---|---|
| أقسام الإنتاج (البقلاوة، الكنافات...) | تحديث حالة أصنافها فقط |
| الكول سنتر | عرض كل الأقسام لحظيًا + الرسائل، بدون تعديل الحالات |
| الإدارة | سجل التغييرات + التقارير + نظرة عامة على الأقسام |
| المطور مجد | كل الصلاحيات + إدارة الأقسام والأصناف ورموز PIN |

## 8) كيفية إضافة ميزات لاحقًا (ملاحظات للمطورين)

- **إضافة صنف جديد أو قسم جديد:** يفضَّل من داخل لوحة المطور مباشرة (بدون لمس الكود).
- **تغيير الألوان:** كل الألوان في `css/variables.css` فقط، عدّل القيم هناك وستنعكس في كل الصفحات تلقائيًا (فاتح وداكن).
- **إضافة حالة جديدة للصنف:** يتطلب تعديل الحقل `status` في جدول `product_statuses` (constraint CHECK) داخل `schema.sql`، بالإضافة لإضافة الحالة في `js/utils.js` (دالتا `statusLabel` و`statusIcon`) وملف `css/components.css` (لون الشارة).
- **الاتصال بـ Supabase:** كل الاتصال في `js/supabase-client.js`. لا تُدرج أو تُعدّل بيانات حساسة مباشرة من الواجهة؛ أضف دالة RPC جديدة في `schema.sql` بدلًا من ذلك حفاظًا على الأمان.
- **التعامل مع انقطاع الإنترنت:** منطقه بالكامل في `js/sync.js` (`OfflineQueue` و`Sync.performOrQueue`).

## 9) ملاحظات أمنية مهمة

- رموز PIN مخزّنة كـ **hash** فقط (عبر `pgcrypto`)، ولا تُقرأ أبدًا كنص صريح من الواجهة.
- كل التعديلات الحساسة (تغيير حالة، رسائل، إجراءات جماعية...) تمر عبر دوال **RPC** آمنة (`security definer`) تتحقق من الجلسة، وليس عبر إدراج/تعديل مباشر بمفتاح anon.
- سياسات **Row Level Security (RLS)** مفعّلة على كل الجداول. جدولا `department_pins` و`sessions` غير قابلين للقراءة إطلاقًا من الواجهة.
- الجلسة صالحة لمدة 12 ساعة ثم تنتهي تلقائيًا وتتطلب إعادة إدخال PIN.

## 10) بيانات تجريبية

تم إدراج 3 أصناف تجريبية (`SMP-001`, `SMP-002`, `SMP-003`) مرتبطة بقسم "البقلاوة" فقط، لتجربة النظام فورًا.
احذفها أو عدّلها من لوحة المطور → تبويب "الأصناف" في أي وقت.
